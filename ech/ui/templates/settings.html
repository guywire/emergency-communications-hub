      AIR QUALITY / SMOKE (AirNow + NASA FIRMS)
    

    

      

        Powers the mesh bot's "smoke"/"aqi" command and the map's 🔥 AQI layer (real AirNow
        stations + FIRMS fire hotspots + NOAA HMS smoke-plume polygons — smoke drifting in from
        a distant fire, e.g. Canada, shows up even with no local fire detected).
        Enabling/disabling the service itself still requires air_quality_service.enabled: true
        in config.yaml + a restart — everything below applies live, no restart needed.

      POTA PROXIMITY ALERTS
    

    

      

        Polls the same POTA activator-spot feed the map's 🏞 POTA layer uses (api.pota.app) and,
        when a new activation appears within range of the hub that hasn't been seen recently, posts
        it to the mesh — e.g. a "pota" MeshCore channel. "Nearby" is a radius around the base
        position (Settings above), same convention as the map's on-demand POTA overlay, not a
        literal rectangle. Enabling itself still requires pota_service.enabled: true
        in config.yaml + a restart — everything below applies live, no restart needed.

      WATER BODIES (EPA quality + NDBC buoys)
    

    

      

        Auto-discovers every EPA-assessed lake/bay/estuary/river near the hub and matches each to
        its nearest live NDBC buoy. No API key needed. Powers the mesh bot's "marine <name>",
        "fish <name>", and "water" commands, plus per-water-body map markers. Enabling itself
        still requires water_body_service.enabled: true in config.yaml + a restart.

      BRIDGE RULES
      Link one channel/addressee on each side
    

    

      

        A bridge joins ONE endpoint on each side — e.g. a mesh channel ↔ APRS messages addressed
        to a group like EMCOMM. Only text crosses (DMs optional), rate-limited, with sender
        attribution; bridged text is never re-bridged and echoes are dropped. Try a new bridge with
        Dry run first and watch its log.

      DATA RETENTION & DISK
      Auto-purge old messages · DB on USB
    

    

      
Messages older than the configured thresholds are deleted hourly. The DB is stored at the path set in database.path in config.yaml — move it to /mnt/usb by updating that path.

      
Hourly message-count-per-adapter is kept separately in a lightweight rollup (90 days) so Analytics volume charts still show history — e.g. yesterday's APRS message count — after the raw message bodies above are purged.

      

        

          
          
        

        

          
          
        

        

          
          
        

        

          
          
        

        

          
          
        

      

      
Before a message is purged above, it's saved to a dated, restorable archive file (message_archive/YYYY-MM-DD.jsonl next to the DB). Archive files themselves are deleted once older than the days set here.

      

        
        
        
      

      

        
        
        
        
      

      

        DB location tip: Set database.path: /mnt/usb/ech.db in /etc/ech/config.yaml to move the DB to the USB drive, then restart ECH. A symlink also works: sudo mv /var/lib/ech/ech.db /mnt/usb/ech.db && sudo ln -s /mnt/usb/ech.db /var/lib/ech/ech.db
