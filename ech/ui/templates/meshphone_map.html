What this map shows

The WT0F MeshPhone Database (wt0f-meshphone.local.mesh) is used as a guide: office names, codes, number patterns and trunk lists. The facts are polled from the mesh every few hours by the PBX named at the top of the page: whether each PBX answers, from the PBXs themselves, and where it is, from the AREDN node it sits behind (its published coordinates and grid square). PBXs that look like a phone system by host name or advertised service but aren't in the directory are added too.

  • PBX up: the PBX answered an IAX2 POKE with a PONG. Asterisk answers this before any login, so it proves the PBX is running and reachable over the mesh. The time is the round trip from the measuring PBX.
  • Moved: the directory's IP address didn't answer, but a PBX-named mesh host of the same admin callsign did (found in the AREDN mesh-wide host list). The directory entry is probably out of date.
  • No answer: none of the addresses tried answered. The PBX may be off, off the mesh, or firewalled against IAX from unknown addresses.
  • No address: the directory has no IP and no PBX-like host was found for the admin's callsign.

Trunks (lines), best evidence first:

  • Our trunk (verified): a trunk of the measuring PBX itself, qualified by its Asterisk, with latency.
  • Reported: PBXs running the MeshPhone generator scripts report their own trunks' Asterisk qualify result (latency or DOWN) when they check in to the WT0F database. Each direction is shown separately with the date of that PBX's last check-in; the line colour is the average latency. Up one way and DOWN the other usually means the trunk is only configured on one side.
  • Not reported: neither PBX reports this trunk. All that can be checked from here is whether both PBXs answer IAX (dotted blue), one doesn't (dotted red), or one has no address (dotted grey).

The white pages come from the last copy of the MeshPhone WhitePages served on the mesh.

Cameras

Every camera or video stream advertised as a service anywhere on the mesh (tagged camera or video by its owner, or named like one), placed at the AREDN node that advertises it. Once a day each one gets the same single request a viewer would make: a web page or snapshot fetch, or an RTSP DESCRIBE. Open means it answered without a password (beyond any the owner put in the advertised link), password needed means it asked for a login. A camera host that isn't the node itself is also checked for the ports camera apps use (RTSP 554/8554, Hikvision 8000, Dahua 37777, Reolink 9000, XMEye 34567), so the table can say which app views it. Passwords in advertised links are masked in the text; the link itself is the owner's, unchanged. /cameras/ opens this page on the cameras.
